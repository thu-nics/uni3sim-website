    02 / 系统设计的约束

    芯片更快，
    系统就一定更快？

    峰值算力之外，容量、带宽、互连和软件栈，共同影响最终可用的系统性能。

    数据到达计算单元之前，容量与带宽都可能成为约束。

    设计空间正在扩大。我们需要在构建系统之前，评估跨层选择带来的影响。

    03 / 连接两道鸿沟

    从硬件能力，
    走到真实服务行为。

    同样的算子，在不同硬件上可能有不同的执行方式。算准 Kernel 时间后，还需要把调度、主机准备和资源竞争放回系统。

    GAP 01

    硬件 → Kernel

    切块、波次、缓存与并发，改变实际执行。

    GAP 02

    Kernel → Serving

    执行完成事件，改变后续组批与请求进度。

    05 / 把调度放回系统

    CPU 在准备，
    Device 在计算。谁在等？

    提前准备下一批请求，可以减少设备等待 CPU 的空档。两批计算的时长保持相同，变化来自它们的调度关系。

    TTFT

    首 Token 延时

    从请求到达到首个有效输出 token 可见。

    TPOT

    每 Token 生成间隔

    首末 token 间隔 ÷（输出 token 数 − 1），输出多于 1 个时适用。

    THROUGHPUT

    输出吞吐

    声明的观测窗口内，输出 token 数与时间之比。

    06 / 多维建模视角

    计算、互连、存储。
    放进同一个系统。

    不同模块回答不同的问题，并共同服务于软硬件协同评估。

    COMPUTE

    ArchPrism

    连接算子、硬件资源与推理服务，解释性能从哪里来。

    建模关注点 ＋
    • 计算工作量与有效资源能力
    • 分层流量、并发与资源依赖
    • Kernel 时间与调度反馈

    INTERCONNECT

    ProtoBridge

    让超节点互连协议的差异，在数据包执行与依赖中显式呈现。

    建模关注点 ＋
    • 通信算子到数据包的转换
    • 协议参数与数据包依赖
    • 共享的数据包执行模块

    MEMORY & STORAGE

    HBF 系统仿真

    把新型存储设备、调度策略与真实推理工作负载连接起来。

    建模关注点 ＋
    • 模块化的 HBF 设备模型
    • 容量与数据调度策略
    • 推理引擎接入与系统级评估
